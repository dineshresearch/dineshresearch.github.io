Simulator & observation / action contract

AeroLab is a benchmark layer on crazyflow, a JAX / MuJoCo MJX quadrotor simulator with a Crazyflie-class (cf2x_T350) airframe. Simulator, classical baselines and the learned comparator run on a commodity CPU-only machine; model inference uses hosted APIs, so the local device does not affect the measured model-side axes.

01From operational scenario to frozen layout

Worlds are authored as MuJoCo primitive geometry; the navigator never sees the ground-truth obstacle list — only sensor observations. Ground-truth clearance, collision and checkpoint events are analytic and evaluator-only.

Two generations coexist and are never pooled into one leaderboard: the structurally distinct v1 scenario geometry (development, verification, visual reference — see Environments) and the instrumented v2 compositions flown by the frozen evaluation. Seeded randomization of obstacle placement and start pose materially changes outcomes, confirming the layouts are not degenerate.

Hard boundaries: models never run the millisecond loop (1.4–3.5 s per language call is one to four orders too slow), never serve as the sole tick-rate obstacle avoider, and never bypass the deterministic shaped-VEL envelope. The pilot never generates mission code or open-vocabulary plans; that is the commander’s role. A deterministic safety gate aborts or holds on any unsafe flag or hard-limit breach.

03The shared action contract (shaped VEL)

Every policy — classical, behavior-cloned or language-model — issues the same shaped world-frame velocity setpoints above the conventional flight controller, so comparisons are about decisions, not interface advantage.

Contract elementBound
Velocity setpoint±1.2 m/s per component (world frame x, y, z)
Yawabsolute world yaw in [−π, π] rad
Hold duration1–10 ticks at 100 Hz
Shaped front endhorizontal accel ≤3.0 m/s², vertical ≤2.0 m/s², per-axis jerk ≤20 m/s³, 0.15 s approach time constant, thrust-vector tilt cap 30°
Excluded by designraw motor thrusts, body rates, mission code generation; controller-side clearance and hard limits are never model-owned

Contract compliance is itself part of piloting competence: violations terminate the episode as invalid_action and the environment is not relaxed. Violations persist and rise on harder held-out layouts and under sensor OOD (see Experiments).

04Sensing and rendering (verified on CPU)

Proprioception (pos, vel, quat, ang-vel, force, torque, rotor RPM) plus two RGB cameras and compiled MJX raycast depth, batched over worlds. Raycast depth is validated against analytic camera→drone geometry (center pixel 1.114 m vs true 1.145 m), not against the MuJoCo offscreen depth buffer, which is near-constant on CPU and kept only as a debug visualization. Missing depth is unknown, never guaranteed free space.

Offscreen RGB renders correctly but is sync-bound: full RGB-D costs ~451 ms/frame (~2.2 fps at 160×120 on CPU), so render rate is decoupled from the 100 Hz control loop and pixels are a budgeted, possibly stale resource. The suite adds configurable resolution, rates, latency (delayed-frame buffer with captured pose) and zone noise; difficulty scales noise and latency, and a separate sensor-OOD condition composes frozen perturbations every sensor tick. Photoreal Gaussian-splat RGB-D is GPU-only and deferred.

05Latency-aware clock protocol

ModeSimulator behaviour while the model thinksWhat it measures
pausedSimulation waits for the model; sim-time advances only on step(n).Decision-quality ceiling (the frozen headline board).
real_timeSim-time advances with wall-time; slow inference becomes drift / loss of control.Latency as a first-class failure source. Specified, not evaluated in this freeze.
hover_while_thinkingA hold keeps the airframe stable during inference, then resumes.Cost of a safe “stop-and-think” fallback. Specified, not evaluated in this freeze.

All frozen runs, LLM and classical alike, use the paused clock: reported scores are zero-latency ceilings, and wall time / token counts measure inference cost, not its effect on flight. Real-time flight is strictly harder.

06Observation encoding & multi-harness layer

A compact lossless observation encoding reduces a full observation from 74,857 to 6,382 characters (0.085×, ~12× fewer observation tokens). Multi-process parallelism measured slower (0.83×) than a warm sequential process on the development machine, motivating the sequential default.

Harness adapterRole in the reported measurementsTurn semantics

Qoder CLIFrontier extension arms (18 episodes)Strict observe–decide–step loop: one observation and one commanded step per turn, recomputed every turn
Codex CLI, Claude CodeSupported adapters for community re-runsHarness-agnostic: same frozen worlds, same gates, same scorer

Identical safety gates across harnesses: dry-run default, held-out test split refused outside the freeze, explicit budget authorization, sequential memory-gated execution, and infrastructure-only retries. The strict loop is the verified mitigation for the harness’s repeated-tool-call scheduler stop, which permission allowlists cannot override. Raw prompts, outputs and traces are logged (provider-default sampling; per-run temperature is not recorded).

Two controller findings shaped the shared interface: an instantaneous far/diagonal waypoint setpoint makes the geometric controller demand large lateral acceleration and flip the drone (fixed by bounded-speed setpoint ramping); and pure yaw rotation beyond 120° was initially misclassified as a flip (fixed by testing body-up alignment, invariant to yaw).
